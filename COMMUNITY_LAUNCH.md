# Maintainer-friendly launch plan (manual; nothing has been published)

AgentFlow's intended audience: maintainers of small/medium Python projects needing durable, human-approved automation and explicit uncertain-state recovery.

1. Publish a public GitHub repository manually after reviewing the license, upstream dependencies, company IP ownership, SECURITY.md and demo fixtures. Avoid claiming Codex for Open Source endorsement.
2. Create a reproducible tagged pre-release, not a stability/security certification. Include exact tested environments and known limitations.
3. Start with offline Echo/Word Count and demonstrate one Issue → approval → validation → report workflow without enabling code execution.
4. Invite five independent maintainers to reproduce `examples/demo.py` and open issues with their host OS, steps and tracebacks. Do not fabricate user stories or metrics.
5. Add a request-for-comments Issue covering PostgreSQL throughput, standalone installer preferences and safe sandbox threat models.
6. Make a small screenshot or 2-minute demo and share it on developer forums with an explicit experimental disclaimer; follow community promotion rules.
7. Record actual clone/download/installation metrics and consented usage feedback, not invented GitHub stars or PyPI numbers. Public evidence matters more than release count for OSS funding applications.

This document includes a rollout plan only. No users have been contacted, and nothing has been published by this artifact build.
